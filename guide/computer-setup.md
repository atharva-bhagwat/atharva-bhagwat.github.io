<nav class="q-crumbs" aria-label="Breadcrumb"><a href="/articles/intro-to-python-biosci/plan">Plan</a><span aria-hidden="true"> / </span><span>Part 2</span></nav><section class="q-stage" id="stage-0" data-stage="0"><header class="q-stage-head"><div class="q-stage-title"><span class="q-stage-num">Stage 11<span class="q-badge is-optional">Level up</span></span></div><div class="q-stage-stars" data-stars-for="0" aria-label="Stars earned in this stage"><span class="q-s" data-part="1">&#9733;</span><span class="q-s" data-part="2">&#9733;</span></div></header><p class="q-promise">Install Python tools on your own machine, once, so your work lasts and you can run bigger jobs.</p><div class="q-prose"><p>In Part 1 you worked in Colab, where everything was ready. That is the best way to learn, but it has limits: sessions reset and your files disappear, big datasets do not fit, and you cannot rebuild exactly the same setup next year. Your own computer fixes all of these, and it needs a little setup, once.</p><h3>Terminal first aid</h3><p>The <strong>terminal</strong> is a window where you type commands instead of clicking. It only does what you tell it. Open it now: <strong>Terminal</strong> on macOS (press <kbd>Cmd</kbd>+<kbd>Space</kbd>, type Terminal), <strong>PowerShell</strong> on Windows (Start menu, type PowerShell). End every line with <kbd>Enter</kbd>.</p><p>A terminal is always standing in one folder, called the <strong>working directory</strong>. These commands cover most of what you will need:</p><div class="q-table-wrap"><table class="q-table"><thead><tr><th>Command</th><th>What it does</th></tr></thead><tbody><tr><td><code>pwd</code></td><td>Print the folder you are standing in.</td></tr><tr><td><code>ls</code></td><td>List what is in this folder.</td></tr><tr><td><code>cd folder_name</code></td><td>Step into a folder. <code>cd ..</code> steps back out.</td></tr><tr><td><code>mkdir new_folder</code></td><td>Make a new folder.</td></tr><tr><td><code>python script.py</code></td><td>Run a Python file.</td></tr></tbody></table></div><ul><li>Press <kbd>Tab</kbd> after typing the first letters of a name and the terminal finishes it.</li><li>Press <kbd>&uarr;</kbd> to bring back the last command. Press <kbd>Ctrl</kbd>+<kbd>C</kbd> to stop something that is running.</li><li>A command that prints nothing usually worked. An error message is read exactly like in Stage 2: start at the last line.</li></ul><h3>1. Install VS Code</h3><p>Download it from <a href="https://code.visualstudio.com/" target="_blank" rel="noopener">code.visualstudio.com</a> and run the installer. VS Code is an editor where you write scripts, run notebooks, browse files and use a terminal in one window.</p><h3>2. Install Miniconda from the terminal</h3><p><strong>conda</strong> makes <strong>environments</strong>: separate boxes, each with its own Python and its own libraries. A project can use one version of pandas while another project uses a different one, and neither breaks the other. <strong>Miniconda</strong> is the small installer. On a Mac, first type <code>uname -m</code>: <code>arm64</code> means Apple silicon, <code>x86_64</code> means Intel.</p><div class="q-os" data-os-group><div class="q-os-tabs" role="tablist" aria-label="Operating system"><button type="button" role="tab" data-os="mac">macOS / Linux</button><button type="button" role="tab" data-os="win">Windows</button></div><div class="q-os-pane" data-os-pane="mac"><div class="qcode"><div class="qcode-bar"><span class="qcode-name">macOS / Linux terminal</span><button class="qcopy" type="button">Copy</button></div><pre><code>uname<span class="w"> </span>-m

Run <code>Set-ExecutionPolicy -Scope CurrentUser RemoteSigned</code>, answer Y, then open a new PowerShell window.</p></aside><aside class="q-callout is-trap"><strong class="q-callout-title">conda mentions "Terms of Service"</strong><p>Newer conda versions may ask you to accept terms before installing packages. The message prints the exact command to run. Copy it, run it, then repeat your first command.</p></aside><h3>3. Make an environment</h3><p>Name it something short. We use <code>pybio</code>. This one command makes it and installs the libraries you used in Part 1:</p><div class="qcode"><div class="qcode-bar"><span class="qcode-name">terminal</span><button class="qcopy" type="button">Copy</button></div><pre><code>conda<span class="w"> </span>create<span class="w"> </span>-n<span class="w"> </span>pybio<span class="w"> </span>-c<span class="w"> </span>conda-forge<span class="w"> </span><span class="nv">python</span><span class="o">=</span><span class="m">3</span>.12<span class="w"> </span>pandas<span class="w"> </span>numpy<span class="w"> </span>matplotlib<span class="w"> </span>seaborn<span class="w"> </span>scipy<span class="w"> </span>ipykernel<span class="w"> </span>-y</code></pre></div><p>Switch into it with <code>activate</code>. Do this every time you open a new terminal. The prompt now starts with <code>(pybio)</code>. If that prefix is missing, you are not inside the environment.</p><div class="qcode"><div class="qcode-bar"><span class="qcode-name">terminal</span><button class="qcopy" type="button">Copy</button></div><pre><code>conda<span class="w"> </span>activate<span class="w"> </span>pybio
conda<span class="w"> </span>env<span class="w"> </span>list</code></pre></div><p><code>conda env list</code> shows every environment you have, with a star next to the active one.</p><h3>4. See what is installed, and add more</h3><p><code>pip</code> is the tool that installs Python libraries. <code>pip list</code> shows everything in the active environment, with version numbers:</p><div class="qcode"><div class="qcode-bar"><span class="qcode-name">terminal</span><button class="qcopy" type="button">Copy</button></div><pre><code>pip<span class="w"> </span>list</code></pre></div><p>To add a library, use <code>pip install</code> and its name. For example, Biopython, which you will use in the optional DNA stage at the end:</p><div class="qcode"><div class="qcode-bar"><span class="qcode-name">terminal</span><button class="qcopy" type="button">Copy</button></div><pre><code>pip<span class="w"> </span>install<span class="w"> </span>biopython
pip<span class="w"> </span>list</code></pre></div><p>Run <code>pip list</code> again and <code>biopython</code> is now in the list. To remove a library: <code>pip uninstall biopython</code>.</p><h3>5. Save and share an environment</h3><p>Six months from now, or on a colleague's laptop, you will want exactly the same setup. There are two files for that.</p><p><strong>environment.yml</strong> describes a whole conda environment. A <strong>YAML</strong> file is just a plain text file of settings written as <code>name: value</code> and lists with dashes. conda writes it for you:</p><div class="qcode"><div class="qcode-bar"><span class="qcode-name">terminal</span><button class="qcopy" type="button">Copy</button></div><pre><code>conda<span class="w"> </span>env<span class="w"> </span><span class="nb">export</span><span class="w"> </span>--from-history<span class="w"> </span>&gt;<span class="w"> </span>environment.yml</code></pre></div><p>Open <code>environment.yml</code> in VS Code to read it. It names the environment, the places packages come from, and the packages you asked for. Anyone can rebuild your environment from it:</p><div class="qcode"><div class="qcode-bar"><span class="qcode-name">terminal</span><button class="qcopy" type="button">Copy</button></div><pre><code>conda<span class="w"> </span>env<span class="w"> </span>create<span class="w"> </span>-f<span class="w"> </span>environment.yml</code></pre></div><p><strong>requirements.txt</strong> is the plainer cousin: just a list of Python libraries, one per line. <code>pip</code> writes and reads it:</p><div class="qcode"><div class="qcode-bar"><span class="qcode-name">terminal</span><button class="qcopy" type="button">Copy</button></div><pre><code>pip<span class="w"> </span>freeze<span class="w"> </span>&gt;<span class="w"> </span>requirements.txt
pip<span class="w"> </span>install<span class="w"> </span>-r<span class="w"> </span>requirements.txt</code></pre></div><ul><li><code>&gt;</code> means "put the output into this file".</li><li><code>-f</code> means "from this file", and <code>-r</code> means "read this list".</li><li>Use <code>environment.yml</code> when others use conda, and <code>requirements.txt</code> when they only use pip. Many projects keep both.</li></ul><h3>6. Add VS Code extensions</h3><p>An <strong>extension</strong> teaches VS Code new skills. You install them with a few clicks:</p><ol><li>Click the <strong>Extensions</strong> icon in the bar on the far left (four squares, one drifting away). Or use the menu <strong>View, then Extensions</strong>. Shortcut: <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>X</kbd> (<kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>X</kbd> on Mac).</li><li>Click the search box at the top. It says <em>Search Extensions in Marketplace</em>.</li><li>Type the name from the table below, for example <code>Python</code>.</li><li>Check the <strong>publisher</strong> under the title and the download count (good ones have millions or hundreds of thousands).</li><li>Click the blue <strong>Install</strong> button. When it changes to a gear icon, it worked. If you see a <strong>Reload</strong> button, click it.</li><li>Repeat for each extension.</li></ol><div class="q-table-wrap"><table class="q-table"><thead><tr><th>Search for</th><th>Publisher</th><th>What it does for you</th></tr></thead><tbody><tr><td><strong>Python</strong></td><td>Microsoft</td><td>Runs <code>.py</code> files and finds your conda environments.</td></tr><tr><td><strong>Jupyter</strong></td><td>Microsoft</td><td>Opens notebooks (<code>.ipynb</code>) inside VS Code.</td></tr><tr><td><strong>Rainbow CSV</strong></td><td>mechatroner</td><td>Colours the columns of a CSV so raw data is readable.</td></tr><tr><td><strong>Error Lens</strong></td><td>usernamehw</td><td>Shows errors at the end of the line that caused them.</td></tr></tbody></table></div><p>To check, type <code>@installed</code> in the search box. All four should be listed.</p><h3>7. Open a notebook in your environment</h3><ol><li><strong>File, then Open Folder</strong>, and choose a folder for your work.</li><li><strong>File, then New File</strong>, choose <em>Jupyter Notebook</em> (or open a notebook you downloaded from Colab with <strong>File, Download, .ipynb</strong>).</li><li>Click <strong>Select Kernel</strong> at the top right, choose <strong>Python Environments</strong>, then pick <code>pybio</code>.</li><li>Run a cell containing the two lines below.</li></ol><div class="qcode"><div class="qcode-bar"><span class="qcode-name">run this in a notebook cell</span><button class="qcopy" type="button">Copy</button></div><pre><code><span class="kn">import</span><span class="w"> </span><span class="nn">sys</span>
<span class="nb">print</span><span class="p">(</span><span class="n">sys</span><span class="o">.</span><span class="n">executable</span><span class="p">)</span></code></pre></div><p>It prints the path of the Python being used. It should contain <code>envs/pybio</code> (or <code>envs\pybio</code> on Windows). If not, pick the kernel again.</p></div><div class="q-practice"><h3>Exercises</h3><p>These are also in the notebook.
