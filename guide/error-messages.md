<nav class="q-crumbs" aria-label="Breadcrumb"><a href="/articles/intro-to-python-biosci/plan">Plan</a><span aria-hidden="true"> / </span><span>Part 1</span></nav><section class="q-stage" id="stage-2" data-stage="2"><header class="q-stage-head"><div class="q-stage-title"><span class="q-stage-num">Stage 2<span class="q-badge is-core">Core</span></span></div><div class="q-stage-stars" data-stars-for="2" aria-label="Stars earned in this stage"><span class="q-s" data-part="1">&#9733;</span><span class="q-s" data-part="2">&#9733;</span></div></header><p class="q-promise">Everyone sees red error text all day. The skill is reading it quickly, and it is easier than it looks.</p><div class="q-prose"><p>An error message is the computer telling you, as clearly as it can, where it got stuck and why. Here is a real one:</p><div class="q-trace"><pre><code><span class="t-dim">---------------------------------------------------------------------------</span>
<span class="t-err">KeyError</span><span class="t-dim">                                  Traceback (most recent call last)</span>
<span class="t-dim">Cell In[4], </span><span class="t-line">line 2</span>
<span class="t-dim">      1 df = pd.read_csv("toy.csv")</span>
<span class="t-arrow">----&gt; 2</span> <span class="t-hot">print(df["Score"].mean())</span>

<span class="t-dim">... (many lines from inside pandas) ...</span>

<span class="t-err">KeyError: 'Score'</span></code></pre></div><ol><li><strong>Start at the bottom.</strong> <code>KeyError: 'Score'</code> says you asked for something by name and it is not there. The first word is the kind of error; the rest is the detail.</li><li><strong>Find your line.</strong> The arrow <code>----&gt; 2</code> points at <em>your</em> code. Ignore the middle section: it is the library's own code, and the mistake is almost never there.</li><li><strong>Check what you assumed.</strong> Which column names really exist? <code>print(df.columns)</code> shows them, and you will see <code>score</code> with a small s. Names must match exactly.</li></ol><h3>The usual errors</h3><div class="q-table-wrap"><table class="q-table"><thead><tr><th>Error</th><th>In plain English</th><th>First thing to try</th></tr></thead><tbody><tr><td><code>SyntaxError</code></td><td>Python could not read the line. Often a missing colon, bracket or quote.</td><td>Look at the marked line and the one above it.</td></tr><tr><td><code>NameError</code></td><td>You used a name Python does not know.</td><td>A typo? Or the cell that creates it has not run (kernel memory).</td></tr><tr><td><code>TypeError</code></td><td>The wrong kind of thing, such as adding text to a number.</td><td><code>print(type(x))</code> for each thing involved.</td></tr><tr><td><code>ValueError</code></td><td>The right kind of thing, but a value it cannot use, such as <code>int("abc")</code>.</td><td>Print the value you passed in.</td></tr><tr><td><code>KeyError</code></td><td>A column or dictionary key is not there.</td><td><code>print(df.columns)</code>. Check spelling and capital letters.</td></tr><tr><td><code>IndexError</code></td><td>You asked for item 10 of a list with 5 items.</td><td><code>print(len(my_list))</code>.</td></tr><tr><td><code>FileNotFoundError</code></td><td>The path points to nothing.</td><td>Check the file name and which folder you are in.</td></tr><tr><td><code>ModuleNotFoundError</code></td><td>The library is not installed here.</td><td>In Colab, run <code>%pip install name</code>.</td></tr></tbody></table></div><h3>A routine that works</h3><ol><li>Read the last line slowly.</li><li>Go to the line the arrow points at. Is it what you meant to write?</li><li>Check what you assumed: <code>print(type(x))</code>, <code>print(df.shape)</code>, <code>print(df.columns)</code>.</li><li>Make the problem smaller: try it on two lines in a fresh cell.</li><li>Suspect the kernel. Restart and run all.</li><li>Search the web with the error type and the library, for example <em>pandas KeyError column</em>, and read why it happens before copying a fix.</li></ol><aside class="q-callout is-why"><strong class="q-callout-title">Loud errors are the good ones</strong><p>The worst bugs give no error at all, just a wrong number. Get in the habit of checking your results: print the number of rows, look at the first few rows, and ask whether the answer is plausible.</p></aside><aside class="q-callout is-tip"><strong class="q-callout-title">Errors arrive one at a time</strong><p>Fixing one error often reveals the next. That is progress. A <code>SyntaxError</code> always comes first, because Python reads the whole cell before running any of it.</p></aside></div><div class="q-practice"><h3>Now practise in Colab</h3><p>You have read the ideas.
